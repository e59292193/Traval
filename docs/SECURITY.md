# 安全、隐私与发布边界

## 当前数据处理

- 照片通过设备文件选择器读取，H5 在内存中解码，不上传服务器或第三方 API。
- 不提取 GPS，不根据照片推断位置，不自动收集照片或输入内容。
- 程序会读取 JPEG 方向字段用于合理确定降采样尺寸；解码器应用 EXIF 方向。不是读取位置信息。
- 没有添加统计 SDK、支付或运行时 AI 服务；uniStatistics 显式关闭。AI 插画和虚构示例由开发阶段预生成，本地使用，不把用户照片发给生成服务。
- 网页初次加载仍需要获取本地/未来托管的 HTML、JS、CSS。开发时有 Vite 相关请求，不能笼统宣称「完全没有网络请求」。实际自动化验收基于本地 production build 的网络记录。
- 不使用 localStorage 保存照片；H5 手动保存的草稿使用同源 IndexedDB（旅行记录、札记、照片 Blob），无云端同步。未保存编辑刷新丢失，隐私模式、换浏览器/域名或清理数据可能无法恢复。共享设备上的其他同源脚本/使用者可能访问数据，不等于加密保险箱。
- 不包含密钥、访问令牌、AppSecret、服务端凭证。AppID 若后续填写只是公开标识，不应混淆为密钥。
- 代码进入 GitHub 不等于网站部署。本次没有进行公网部署。

## 依赖安全审计（发布阻塞）

检查命令：`npm audit --omit=dev --json`，实际快照见 `docs/evidence/npm-audit-production.json`。

当前锁定 uni-app 非 alpha 发行版本，以及其匹配的 Vue 3.4.21 / Vite 5.2.8；审计报告存在 high 级别提示。npm 的分类包括框架引入的编译依赖，不能把其全部等同于浏览器运行时可利用漏洞，也不能据此声称安全。

没有使用 `npm audit fix --force` 强制换版，避免静默破坏 uni-app 的匹配依赖及小程序编译。项目负责人在商业发布前需要：

1. 对生产运行代码、开发服务器和构建链分别评估报告中的实际攻击面。
2. 选择受支持的 DCloud / Vue / Vite 升级组合，确认许可与兼容性，再整体更新锁文件。
3. 重新完成核心测试、H5 浏览器测试和小程序真机验证。
4. 重新运行安全审计并对未修复项形成明确处置记录。

在此之前，仅将当前成果作为本地原型使用，**不要直接部署成商业服务或将开发服务器暴露公网**。这份原型不是安全审计、法律审核或平台合规通过证明。

## 框架默认外链处理

端到端网络验收发现 uni-app 的 H5 框架会在 3 秒后预加载 `cdn.dcloud.net.cn` 上的导航阴影图片。项目使用自定义导航，并不需要这张图。现已通过 `vite.config.ts` 的构建插件移除 CSS 中这些特定框架阴影 URL，并在全局样式禁用对应预加载动画；没有改写 node_modules。正式构建应通过 E2E 的「无外部请求」检查，框架升级后必须回归。此处理不等同于修复依赖安全漏洞。

## V0.2 静态素材和字体

地图、水彩插画、贴纸、Caveat 字体与可选 AI 示例全部本地内嵌，不从图片/字体 CDN 读取。地图是静态排版，没有获取用户位置或地图 API。样例逐张标记，替换/清空不会把残留示例冒充用户照片。地图与素材许可、最终拼贴审图要求见 MAP-AND-ART.md；原有依赖审计问题没有因视觉升级而自动修复。

## V0.3 地图与草稿

- GeoJSON 和城市目录随构建本地打包，无在线 geocoding、瓦片、GPS、第三方统计或地图密钥。初始网页下载与后续业务操作网络应区别描述。
- 存储由用户显式触发。保存当前槽位及历史记录引用的降采样 JPEG（重新编码），不保存输入原文件的 EXIF；不读取原文件地理位置。草稿保存失败保留当前编辑；损坏/不兼容草稿在替换前拒绝。
- 自定义地点是手动原始底图坐标，不自动转换 WGS84/GCJ-02/BD-09，也不保证底图测绘精度。源文件许可/最终公开发布审查未核实。
- 当前模型支持上限100次旅行、500个到访记录、4个手账照片槽位、最多32张保留照片；这是输入保护，不是经过手机内存压力验证的容量承诺。

## V0.3 本次审计快照

新引入的ECharts已选择6.1.0，修复审计对初选5.6.0指出的moderate XSS问题；tooltip仍采用richText而非拼接HTML。复测后的生产口径仍有41项（25 high、10 moderate、6 low），主要来自既有依赖链，见`evidence/v3/npm-audit-production.json`。未使用强制升级掩盖兼容性风险；上线前仍需整体依赖升级评估。
